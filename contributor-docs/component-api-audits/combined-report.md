## Most consequential findings

- All five components lack the ADR-003 sx root prop; fixes target the appropriate rendered surface while preserving existing props and refs.
- Tooltip V2, Dialog, and SelectPanel lack a consumer-composable parts surface; ActionMenu exposes parts with gaps in as and render; Button's interactive leaf lacks both render forms.
- Tooltip V2 and Dialog own or report visibility transitions without the required new object callback. ActionMenu and SelectPanel also expose different open control/default models for a shared concept.
- Tooltip V2, Dialog, and SelectPanel have configured merge behavior that differs from ADR-025. New part APIs should follow the gist's consumer-first order; changes to legacy configured surfaces need an additive or versioned migration.

No current-contract defects were established and there are no open BLOCKs. These grades measure accepted-target gaps, with the current API contract retained as separate context.

#### Tooltip V2 — Target gaps

##### Tooltip V2 — T-F1 — Add a consumer-composable Tooltip parts surface

**Classification / severity / owner:** ADR GAP · FIX · PART-01, section 1; affected checks: PART-01, PART-DOCS, PART-AS, PART-RENDER, MERGE-HANDLER, MERGE-CLASS, MERGE-STYLE-ATTR, MERGE-REF, MERGE-BEHAVIOR.

**Reachable consumer:** A consumer composes Tooltip with an interactive trigger such as ActionMenu.Button; ActionMenu has an explicit Tooltip-wrapped anchor path.

**Observed gap:** Tooltip requires one child, clones it to inject behavior, and documents no subcomponents. It has no parts surface for consumer-controlled trigger and tooltip regions.

**Additive fix:** Add an opt-in parts entry point with trigger and tooltip-surface ownership while retaining the existing <Tooltip text> child API. Keep exact part names and default elements pending maintainer review.

**Pinned citations:** packages/react/src/TooltipV2/Tooltip.tsx:135-140 @ 2128032dca65a1bd565fe382c2e91c638c6473a4; packages/react/src/TooltipV2/Tooltip.tsx:327-352 @ 2128032dca65a1bd565fe382c2e91c638c6473a4; packages/react/src/TooltipV2/Tooltip.docs.json:71 @ 2128032dca65a1bd565fe382c2e91c638c6473a4; packages/react/src/ActionMenu/ActionMenu.tsx:126-140 @ 2128032dca65a1bd565fe382c2e91c638c6473a4

##### Tooltip V2 — T-F2 — Add the ADR-003 sx root prop

**Classification / severity / owner:** ADR GAP · FIX · API-01, section 2; affected checks: API-01.

**Reachable consumer:** A consumer needs a local style adjustment to the Tooltip surface without replacing its trigger.

**Observed gap:** Tooltip renders a DOM surface and accepts HTML attributes, but TooltipProps does not include sx.

**Additive fix:** Add sx to TooltipProps and route it to the owned tooltip surface while preserving the existing trigger ref behavior and all current props.

**Pinned citations:** contributor-docs/adrs/adr-003-prop-norms.md:24-26 @ 2128032dca65a1bd565fe382c2e91c638c6473a4; packages/react/src/TooltipV2/Tooltip.tsx:20-48 @ 2128032dca65a1bd565fe382c2e91c638c6473a4; packages/react/src/TooltipV2/Tooltip.tsx:392-397 @ 2128032dca65a1bd565fe382c2e91c638c6473a4

##### Tooltip V2 — T-F3 — Align configured Tooltip merging with ADR-025

**Classification / severity / owner:** ADR GAP · FIX · MERGE-CONFIG, section 3; affected checks: MERGE-CONFIG.

**Reachable consumer:** A consumer supplies onTouchEnd and className while Tooltip adds touch dismissal and its own surface class.

**Observed gap:** The consumer touch handler runs before Primer dismissal, and consumer className precedes the component class, contrary to ADR-025 configured merge precedence.

**Additive fix:** Keep the legacy merge behavior during transition; implement the target merge behavior on the new parts API and provide an explicit opt-in or versioned migration before changing the existing wrapper.

**Pinned citations:** contributor-docs/adrs/adr-025-prop-merging.md:24-50 @ 2128032dca65a1bd565fe382c2e91c638c6473a4; packages/react/src/TooltipV2/Tooltip.tsx:355-361 @ 2128032dca65a1bd565fe382c2e91c638c6473a4; packages/react/src/TooltipV2/Tooltip.tsx:392-394 @ 2128032dca65a1bd565fe382c2e91c638c6473a4

##### Tooltip V2 — T-F4 — Expose Tooltip open-state transitions

**Classification / severity / owner:** ADR GAP · FIX · STATE-CALLBACK, section 4; affected checks: STATE-CALLBACK, NAMES-DEFAULTS.

**Reachable consumer:** A consumer needs to coordinate tooltip visibility with an adjacent interactive control or observe the transition.

**Observed gap:** Tooltip owns open state but exposes no transition callback.

**Additive fix:** Add an object-shaped onOpenChange callback with value, reason, event when present, and synchronous cancel; keep Tooltip's existing props and uncontrolled behavior.

**Pinned citations:** packages/react/src/TooltipV2/Tooltip.tsx:20-48 @ 2128032dca65a1bd565fe382c2e91c638c6473a4; packages/react/src/TooltipV2/Tooltip.tsx:153-161 @ 2128032dca65a1bd565fe382c2e91c638c6473a4

##### Button — B-F1 — Add both render forms to the Button leaf part

**Classification / severity / owner:** ADR GAP · FIX · PART-RENDER, section 2; affected checks: PART-RENDER, MERGE-HANDLER, MERGE-CLASS, MERGE-STYLE-ATTR, MERGE-REF, MERGE-BEHAVIOR.

**Observed gap:** Button supports as but has no render-element or render-function API.

**Additive fix:** Add element and function render forms to the root part while preserving as, ref, and existing props. Decide how simultaneous as and render values interact before shipping.
