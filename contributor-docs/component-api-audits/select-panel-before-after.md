## What changed

Tyler’s decomposition adds `SelectPanel.Root` and named parts, giving consumers control over panel layout, optional regions, and children-based composition while retaining the configured API. The new API also adds controlled/uncontrolled open state with `defaultOpen=false`.

The whole-component grade includes gaps on both APIs. The composable surface misses parts substitution, merge, ref, callback, documentation, selector, styling, and interaction-evidence requirements; the configured API retains its class-merge and shared open-state gaps. The seven failing tests contribute one access-behavior finding, with the related test-evidence row covered by that finding.

### Main fixes in the decomposition

1. Added an opt-in named-parts composition surface while retaining the existing configured API.
2. Let consumers own layout and choose which optional regions to render.
3. Added controlled/uncontrolled open state with `defaultOpen=false` while preserving the configured callback signature.

### Largest remaining gaps

1. Complete `as` support and part-owned behavior on every composable part; `PART-RENDER` remains deferred from scoring.
2. Align configured and composable merging with their respective accepted policies, including consumer-first part classes, a separate handler skip contract, and merged refs.
3. Add object-shaped transition callbacks and resolve the seven reproducible behavior failures; add Playwright coverage for the composable path.

Part-level documentation and stable selectors are also missing, and all runtime SelectPanel CSS Modules need the named component layer.
