# SelectPanel

`SelectPanel` is a data-driven, filterable picker built with Base UI Combobox and Primer's Popover and Dialog primitives.

<Canvas of={Stories.Default} />

## Props

<Controls of={Stories.Playground} />

`SelectPanelProps` requires `items`, `selected`, and `onSelectedChange`. It supports anchored and modal presentation, controlled or uncontrolled visibility and filtering, external anchors, selected-option ordering, grouped items, dividers, inactive or disabled items, loading states, notices, custom messages, secondary actions, select-all, item renderers, virtualization, scroll-end loading, and sizing.

## Import and configuration

```tsx
import {SelectPanel} from '@primer/react-tailwind/SelectPanel'
```

Use the configured component for the standard picker pattern. Use `SelectPanel.Root` and its parts when the consumer needs to control structure; both APIs share Primer styling.

`SelectPanel.SecondaryActionButton`, `SelectPanel.SecondaryActionLink`, and `SelectPanel.Message` are the supported presentational helpers for the configured API.

## Composing parts

```tsx
<SelectPanel.Root<string> items={['bug', 'enhancement']}>
  <SelectPanel.Trigger aria-label="Labels">Labels</SelectPanel.Trigger>
  <SelectPanel.Portal>
    <SelectPanel.Positioner>
      <SelectPanel.Popup>
        <SelectPanel.Header>
          <SelectPanel.Title>Labels</SelectPanel.Title>
        </SelectPanel.Header>
        <SelectPanel.Filter aria-label="Filter labels" />
        <SelectPanel.List aria-label="Labels">
          {(label: string) => (
            <SelectPanel.Item key={label} value={label}>
              <SelectPanel.SelectionIndicator />
              {label}
            </SelectPanel.Item>
          )}
        </SelectPanel.List>
        <SelectPanel.Empty>
          <SelectPanel.Message title="No labels available" />
        </SelectPanel.Empty>
      </SelectPanel.Popup>
    </SelectPanel.Positioner>
  </SelectPanel.Portal>
</SelectPanel.Root>
```

Name the trigger explicitly with `aria-label` or a visible label association. Include `Title` to name the popup, or name `Popup` explicitly with `aria-label`/`aria-labelledby`; when overriding a title's ID, also provide `Popup`'s `aria-labelledby`. Always name the list and any filter. Parts forward refs and DOM props to their named element; Base UI-backed parts retain `render`, state-aware classes/styles, and primitive events.

For a picker without a filter, set `filterable={false}` on `Root`, omit `Filter`/`Empty`/`Collection`, and map explicit `Item` children into `List`. That root uses Base UI Select, with typeahead and option focus rather than input active descendants. Disabled options remain focusable for discovery but cannot be selected. `SelectionIndicator` defaults to a checkmark or checkbox according to `multiple`; override `variant` for a radio visual.

`Surface` is the presentational body for embedding the picker in an existing Popover or Dialog; `Popup` is the explicit floating Base UI behavior part. `Header`, `Title`, `GroupLabel`, `Loading`, and `Footer` keep Primer styling while allowing arbitrary children. Put footer actions outside `List`. Show `Loading` instead of `List` while fetching; it announces its children as a status. Compose `Group` and `GroupLabel` with `Collection` for filtered sections. There is no child extraction or region registration, so consumer wrappers work normally.

Parts use Base UI's `value/defaultValue/onValueChange` and `open/defaultOpen/onOpenChange` contracts; filterable roots also support `inputValue/defaultInputValue/onInputValueChange`. The configured API retains automatic mobile dialogs, staged Save/Cancel selection, select-all, selected-first sorting, and virtualization. See the composition stories for input-free selection, custom rows and footer actions, and grouped creation.

## Controlled and uncontrolled

Selection is controlled by `selected` and `onSelectedChange`; visibility uses `open`/`onOpenChange` or `defaultOpen`; search uses `filterValue`/`onFilterChange` or `defaultFilterValue`. When `filterValue` or `onFilterChange` is provided, `items` is the consumer-filtered collection for remote or fuzzy search; otherwise SelectPanel filters simple text locally. Selected values remain selected even when their items are outside the current filtered `items` collection. Item IDs are type-sensitive, so numeric `1` and string `'1'` remain separate; id-less items use object identity.

The forwarded ref and `overlayProps` target the popup or dialog element. `renderAnchor={null}` requires `anchorRef` and attaches the panel to an external trigger. `renderGroup` wraps every configured group unless that group's `groupMetadata[].renderGroup` overrides it.

## Accessibility, forms, and keyboard

The trigger has a button name from selected content, placeholder, or title. The filter input uses the normal input background, is named by `inputLabel` or placeholder text, and references the list with `aria-controls` only while the list is rendered. The list uses `actionListProps['aria-label']`, `aria-label`, or the string title. Base UI owns active descendants, disabled options, Escape and outside dismissal, focus restoration, portals, collision-aware placement, and option semantics. Arrow keys navigate and Enter selects. Modal and narrow-screen panels lock document scrolling, focus the filter, expose Cancel/Save controls where selection is deferred, and restore focus to their trigger. The component is not a native form field; model submitted values in application state.

## Events and state attributes

`onSelectedChange` receives Base UI selection details when an option causes the change. `onOpenChange` receives a stable SelectPanel gesture (`anchor-click`, `anchor-key-press`, `click-outside`, `escape`, `selection`, or `cancel`). `onFilterChange` receives Base UI input details. Stable selectors include `SelectPanel`, `.Content`, `.Header`, `.Title`, `.Subtitle`, `.Filter`, `.List`, `.Item`, `.GroupHeading`, `.Notice`, `.Message`, and `.Footer`; options expose Base UI selection, highlight, and disabled state attributes.
