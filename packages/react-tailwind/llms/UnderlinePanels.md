# UnderlinePanels

`UnderlinePanels` is a tab-and-panel composition with an underlined tab list.

Import: `import {UnderlinePanels} from '@primer/react-tailwind/UnderlinePanels'`

Read [package guidance](../AGENTS.md) for setup, styling, and shared composition contracts.

## Import and usage

```tsx
import {UnderlinePanels} from '@primer/react-tailwind/UnderlinePanels'
;<UnderlinePanels defaultValue="overview">
  <UnderlinePanels.List aria-label="Repository sections">
    <UnderlinePanels.Tab value="overview">Overview</UnderlinePanels.Tab>
  </UnderlinePanels.List>
  <UnderlinePanels.Panel value="overview">Repository activity.</UnderlinePanels.Panel>
</UnderlinePanels>
```

Pair each tab and panel by `value`, provide an accessible name for the list, and use this pattern for local content switching rather than navigation.

### Wrapper and tablist styling

`UnderlinePanels.List wrapperClassName` styles the outer layout wrapper; `className`, `style`, other DOM props, and the forwarded ref still target the inner Base UI tablist. The root's `className` styles the whole tab-and-panel composition. Move legacy wrapper-only classes to `List wrapperClassName`.

The wrapper's bottom border is an inset shadow. Use `wrapperClassName="px-0 pt-0 shadow-none"` to remove its horizontal/top padding and bottom border without targeting internal selectors. Tailwind utilities merge with the `primer:`-prefixed defaults, removing conflicting classes such as `primer:px-4` rather than leaving both on the element.

The default inset uses the package-owned `primer:px-4` class, which legacy host `.px-4 !important` rules do not match. Classes you pass are generated by your app's Tailwind build under their own names, so an unprefixed `px-4` in `wrapperClassName` can still meet such a rule; use `px-[16px]` to request Primer Tailwind's 16px inset or `px-[24px]` to request the legacy 24px inset. Verify computed insets in mixed installations, because the prefixed stylesheet's cascade alongside host CSS has not yet been verified.

### Controlled and uncontrolled selection

Pass `value` and `onChange` to control the selected tab, or `defaultValue` to let the component manage selection. `onChange` receives `{value}` when a user selects a different tab.

```tsx
const [refType, setRefType] = React.useState('branch')

<UnderlinePanels value={refType} onChange={({value}) => setRefType(value)}>
  <UnderlinePanels.List aria-label="Ref type">
    <UnderlinePanels.Tab value="branch">Branches</UnderlinePanels.Tab>
    <UnderlinePanels.Tab value="tag">Tags</UnderlinePanels.Tab>
  </UnderlinePanels.List>
  <UnderlinePanels.Panel value="branch">Find or create a branch…</UnderlinePanels.Panel>
  <UnderlinePanels.Panel value="tag">Search or create a new tag…</UnderlinePanels.Panel>
</UnderlinePanels>
```

### Activation mode

By default, arrow-key navigation selects the focused tab (`activationMode="automatic"`). Set `activationMode="manual"` so the Arrow, Home, and End keys only move focus and Enter, Space, or a click commits the selection. Prefer manual activation when showing a panel triggers async work such as a fetch.

### In an overlay

`UnderlinePanels` can be composed inside `AnchoredOverlay.Content`, for example to pick a ref type. The tab list keeps its own roving tab stop.

`activationMode="manual"` also works inside the package-owned overlay: initial focus stays on the selected tab, arrow keys move focus without changing selection, and Enter commits it. The overlay story exposes activation-mode and StrictMode controls for repeated open/close checks. This coverage uses the package's Base UI Popover, not a separate legacy focus trap; the alignment notes describe the consumer-owned readiness fix for that integration.

Forwards unrecognized props to Base UI's [`Tabs.Root`](https://base-ui.com/react/components/tabs#root), so it also accepts that part's props.

## Props

- `activationMode`: `TabsActivationMode` — Default `'automatic'`. Whether arrow-key focus also selects a tab. `automatic` selects the focused tab; `manual` only moves focus, and Enter, Space, or a click commits the selection. An explicit `TabList` `activateOnFocus` takes precedence.
- `defaultValue`: `string` — Value of the tab selected on first render when uncontrolled.
- `loadingCounters`: `boolean` — Default `false`. Shows placeholders in place of tab counters while their values load.
- `onChange`: `((details: { value: string; }) => void)` — Called with the newly selected tab's `value` when a user selects a different tab. Automatic fallbacks, such as a missing or disabled selection, and re-selecting the current tab do not call it.
- `value`: `string` — Value of the selected tab when controlled. Update it from `onChange` or `onValueChange`.

## UnderlinePanels.List

Forwards unrecognized props to Base UI's [`Tabs.List`](https://base-ui.com/react/components/tabs#list), so it also accepts that part's props.

- `wrapperClassName`: `string` — Styles the outer layout and bottom-border wrapper without changing the tablist's className or ref.

## UnderlinePanels.Tab

Forwards unrecognized props to Base UI's [`Tabs.Tab`](https://base-ui.com/react/components/tabs#tab), so it also accepts that part's props.

- `counter`: `React.ReactNode` — Number shown after the tab's label.
- `icon`: `React.ElementType` — Icon component shown before the tab's label.
- `leadingVisual`: `React.ReactNode` — Visual shown before the tab's label, as an alternative to `icon`.

## UnderlinePanels.Panel

Forwards unrecognized props to Base UI's [`Tabs.Panel`](https://base-ui.com/react/components/tabs#panel), so it also accepts that part's props.

## Differences from `@primer/react`

- Use `value`/`defaultValue` with `onChange({value})` for tab selection, matching upstream. `onChange` fires only for user-initiated selection of a different tab; Base UI's `onValueChange(value, eventDetails)` remains available when you need the event details or want to cancel a change.
- **Parity — activation mode:** `activationMode="manual"` keeps upstream's behavior: Arrow, Home, and End keys move focus without selecting, and Enter, Space, or click commits the selection.
- **Intentional difference — explicit composition:** tabs live in `UnderlinePanels.List` and every tab and panel needs an explicit `value`; positional pairing and `aria-selected`/`onSelect` tab props are not supported.
- **Class placement:** the root's `className` styles the whole tab-and-panel composition, and `List className`, `style`, DOM props, and ref target the Base UI tablist. Move legacy outer-wrapper padding/border classes to `List wrapperClassName`. Use `wrapperClassName="px-0 pt-0 shadow-none"` to remove the default wrapper padding and inset-shadow bottom border; conflicting default utilities are removed, so host `.px-4` overrides do not affect that wrapper.
- **Host utility collision:** the default 16px inset uses the package-owned `primer:px-4` class, which legacy host `.px-4 !important` (24px) rules do not match. A caller-supplied unprefixed `px-4` is still subject to host CSS, so use `wrapperClassName="px-[16px]"` or `px-[24px]` to select an inset explicitly. The prefixed stylesheet's emission and cascade alongside host CSS are not yet verified.
- **Intentional difference — unmatched value:** a `value` that matches no tab leaves no tab selected instead of clamping to the first tab with a development warning. An uncontrolled `defaultValue` that matches no tab falls back to the first enabled tab without calling `onChange`.
- **Overlay composition:** `UnderlinePanels` can render inside `AnchoredOverlay.Content`; the overlay does not add a competing focus zone, so the tab list keeps exactly one tabbable tab.
- **Legacy-overlay integration:** consumer tracing with Base UI 1.8 found that an independent legacy focus trap can focus the first tab before its composite index is registered, leaving the highlighted index at `-1` despite an intact tab registry. The consumer reports resolving this in its compatibility overlay by waiting for a layout-driven readiness commit before enabling the existing trap and initial focus, without removing trapping or adding an arrow-key fallback or dependency patch. This fix belongs to that adapter, not the package-owned Popover; mixed-overlay coverage remains consumer-owned.
- Do not treat counters as the tab's accessible name.
- Query the active panel only; inactive panels need not remain mounted.
- Icons remain visible while the tab list scrolls horizontally at constrained widths, matching the current upstream rendering even though its historical story name describes hiding icons.
- Use `render` for behavior composition and `className`, not `sx` or styled-system props.
